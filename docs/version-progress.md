# 版本進度

`/version-progress` 比較繁中服正式開服以來與國際服的版本距離。預設「包含小版本」，7.01、7.05、7.11、7.15 等均有獨立節點；7.16、7.18、7.21 因無獨立繁中版本號而省略圖表刻度，仍保留在對照表及版本選單。切成「主要版本」後，摘要、圖表與對照表同步切換。點選圖表節點、表格版本或版本選單會同步詳情，`patchScope` 與 `patch` query 支援分享、重載、上一頁及下一頁。

標題區沿用其他頁面的共用版型與響應式規則，副標為「Final Fantasy XIV 繁中服・版本進度」，主標題為「版本進度」。

## 資料與責任

- `config/version_progress.json` 保存按官方發布順序排列的版本字串、雙方日期、分類、來源及合併說明。`note` 可用換行分段；選填的 `note_sources` 以 `{ label, source }` 連結來源鍵值，由建置器驗證並轉為 `note_links` 供詳情區呈現。內容對照與發布日期各有來源，避免回溯公告或較後版本筆記取代原本的上線日期依據。`verified_through` 是人工核對截止日，用於判定已確認發布的版本、歷史上線間隔及推測模型。畫面的持續中時長、主版本總時長與開服天數另依台灣當日日期更新，不能把日期經過解讀為新版本已確認上線。
- `scripts/build_version_progress.mjs` 在 Node 端驗證資料，計算同版本間隔、各服版本時長、節點差、目前版本及時間軸階段。每個視圖的版本列提供 `international_duration` 與 `tc_duration`，格式為 `{ days: number, ongoing: boolean }` 或 `null`；`groups` 以主要版本的 `patch`、完整 `rows` 與兩服主版週期時長提供跨列分組。Vue 對 `ongoing` 時長補上核對日至台灣今天經過的日曆天數；同版本上線間隔與前版比較直接使用固定的 `lag_days` 及 `lag_reduction`。Vite 插件在開發與正式建置時將結果序列化為 `virtual:version-progress` 靜態 JSON 模組；不發送 FFLogs 請求、不寫入 `data/` 或 `public/data/`。
- `src/pages/VersionProgressPage.vue` 只做顯示、篩選、選取與依容器寬度投影 SVG 座標。`src/composables/useVersionProgressClock.js` 提供台灣當日日序，常駐頁面每 30 秒檢查跨日，視窗取得焦點或分頁可見狀態變動時立即刷新，離頁時清除計時器與事件。`src/utils/versionProgress.js` 以 `取得版本顯示時長` 更新實際持續中的時長；摘要使用建置後的固定上線間隔，版本面板與詳情用 `格式化版本間隔` 顯示相同的發布日差，不修改靜態資料、排序或推測統計。每個主版本使用一個 `tbody`，兩服總時長以 `rowspan` 跨越所屬小版；各版時長放在上線日期下方。手機時間軸保留可讀寬度並可左右捲動；對照表在 960px 以下改為直向卡片，兩服主版總時長只在每組開頭顯示一次。主題沿用共用 token。
- `/version-progress` 已納入導覽、分享網址、公開資料基底辨識與 `build_spa_fallback.mjs` 的 SEO／OG／sitemap。

這份設定與 `config/game_versions.json` 的競技版本、過版規則、爬蟲開放時間完全分開。新增時間軸小版本不得順便改動玩家成績的版本分類或重建歷史資料。

## 比較定義

1. 開服基準採繁中服 2025-12-10 正式上市；2025-11-27 搶先體驗只作說明。國際服 7.0 同樣採 2024-07-02 正式上市日。
2. 同版本上線間隔 `lag_days`＝繁中服發布日－國際服發布日，兩服已發布後即固定，不累加今天或核對日經過的時間。摘要比較繁中最近兩次已核對且有雙服日期的獨立更新，由 `previous_comparable`、`latest_comparable` 及 `lag_reduction` 提供；`lag_reduction`＝前版間隔－本版間隔，正值顯示縮短、負值顯示增加、零顯示「間隔相同」。表格與詳情使用同一份發布日差，兩種篩選及猜測模式一致；合併版與尚未上線的公告／活動預告不算前版，主要版本模式也不退回前一主版。只有開服版本時，前版與變化量為 `null`。正式核對後續更新後才替換比較版本，單純跨日不能切換目前版本。日期視為公告的日曆日，轉 UTC 日序計算，不以維護時刻計算小時差。
3. 版本字串保持完整，依設定清單排序，禁止用浮點數相減。節點差計算在繁中目前版之後、國際目前版以前（含端點）的國際服已發布節點；主要版本模式只計算 `major: true`。這不是待更新次數或內容完成率。
4. `tc: null` 代表尚未核對到獨立繁中上線日期；可能是合併推出，不能當成內容未開放。目前 7.16、7.18 的部分內容對應繁中服 7.15，7.21、7.3 的部分內容對應繁中服 7.2，使用 `merged_into`、`note` 與 `tc_source` 連結說明；不虛構獨立繁中日期或整版等價關係。已有獨立繁中日期的版本若只有部分功能提前，僅在說明記錄，不填入 `merged_into`。
5. 日期晚於核對日的已公告版本只顯示日期與待上線狀態，不提升目前版本、不列入同版本上線間隔或實際時間軸。猜測模式另提供延伸到兩服進度交會的情境估算，不補寫正式日期。
6. `tc_version_omitted: true` 明確標示沒有獨立繁中版本號的 7.16、7.18、7.21；僅適用小版本，必須有 `merged_into` 且目標是已發布、順序在前的繁中版本，可為主版或小版。圖表的刻度與兩條折線節點均省略這三版，座標依剩餘階段重新排列；面板與詳情固定顯示「與小版本合併，因此無此版本號。」，逗號後強制換行。完整日期、內容說明、來源、選單與分享網址仍保留。`merged_into` 本身只代表部分內容對照，不會自動隱藏 7.3 等其他版本。
7. 繁中服尚未上線且未公告日期的版本，面板與對照表統一顯示「尚未公告改版日期」，不另列部分內容合併狀態。未上線版本的詳情收起內容說明、內容來源與「尚無同版本間隔」；表格也不把舊版內容筆記列為該版的繁中上線來源。提前收錄的資訊仍保存在設定，並於已上線版本（例如 7.2）呈現。7.16、7.18、7.21 沿用上述已合併說明；未來若公告日期，仍顯示實際日期與待上線狀態。

8. 各版時長放在該服上線日期下方。時長＝該服下一個已上線版本日期－本版上線日期；包含小版本時採完整更新順序，主要版本模式則算至下一個主要版本。各服分開計算，沒有獨立繁中日期的版本不會截斷前版；圖表省略的 7.16、7.18、7.21 仍是國際服的有效切點。所選範圍的現行版本顯示時計至台灣今日，標示「持續增加中」；原始 `days` 仍保留核對日的值，由顯示工具加上 `今日－end_day`；未上線、未公告或沒有獨立繁中版本號者，時長為 `null`，日期下方不另加說明。日曆日相減不加一天，上線當日為 0 天；已公告但仍在核對日之後的下一版不提前終止現行時長。
9. 「國際服主版本總時長」與「繁中服主版本總時長」各有一個跨列欄位，依 `major: true` 與官方發布順序切分群組，不用浮點數或字串前綴推測。7.0 群組包含 7.0、7.01、7.05；7.1 群組包含 7.1、7.11、7.15、7.16、7.18。總時長沿用主要版本模式的完整週期，沒有獨立上線的繁中小版不會重複計入；現行主版與其所屬小版一起計至台灣今日，未上線的主版總時長顯示「—」。切換主要版本時，每組只剩主版本一列，總時長不變。滑鼠移入同組任一小版本時，兩服共用的總時長欄位一起反白；鍵盤聚焦也套用相同的群組提示，平時沿用面板底色。

截至 2026-09-12，繁中服 7.2、國際服 7.56；版本標籤相隔 13 個已收錄更新節點，主要版本相隔 3 個。摘要比較 7.15 的 553 天與 7.2 的 490 天，顯示「553 → 490 天、縮短 63 天」，跨日後保持固定。7.25 的活動預告若於 2026-09-29 確認實際上線，其國際服日期 2025-05-27 至繁中發布日也相隔 490 天，屆時摘要才改為「490 → 490 天、間隔相同」。開服至核對日為 276 天；畫面「開服至今」依台灣今日增加，例如 2026-09-13 為 277 天。一般模式的實際折線也將最後已核對版本延伸至今天；猜測模式仍保留核對日的分界及固定推測排程。

摘要不再顯示每日上升的符號或「計至台灣今日」。前版比較若縮短則顯示綠色下降箭頭，若增加則顯示紅色上升箭頭，間隔相同時不顯示箭頭；提示明確說明相較前版的固定變化量，不宣稱日期正在上升或縮短。`src/components/VersionTrendHint.vue` 支援滑鼠懸停、鍵盤聚焦與點擊固定提示，再次點擊、點擊外側、移開焦點或按 Escape 可關閉；提示位置會避開手機畫面邊界。

完整對照表共 22 列，包含小版本的圖表顯示 19 個階段；摘要的版本標籤差仍以完整已發布清單計算，不受圖表省略影響。

包含小版本時，國際服 7.0 時長 14 天、繁中服 7.0 時長 62 天；主要版本模式對應 133 天與 132 天。截至核對日，繁中服 7.2 已持續 46 天，國際服 7.56 已持續 4 天；台灣時間 2026-09-13 顯示時則分別為 47 天與 5 天。已結束版本與推測完整週期不隨今日增加。

## 當日倒數與排程提示

四項日期呈現共用頁面的台灣時鐘，兩處 `VersionForecastSummary` 由 `today` prop 接收同一日序；不重算模型，也不新增計時器、網址參數或持久化狀態：

1. 追上剩餘天數使用 `catch_up.day－今日`，顯示「距今天約 X 天」；當日改為「推測於今日追上，實際進度待核對。」，超過日期則顯示已過幾天及待重新核對。原推測日期保留，不能自動宣稱已追上。`days_to_catch_up` 仍保存距核對日的建置值；`elapsed_to_catch_up` 是開服日至模型追上日的完整期間，保持固定。已核對追上的結果顯示「核對時已追上」，不再提供倒數。
2. 下一版提供 Node 正規化的 `next.day`，包含樣本不足時的公告／預告分支。摘要、表格與選取詳情只對目前篩選的下一版顯示「還有 X 天」；一般模式也可顯示已有公告或活動預告的倒數，但不為未公告日期補造日期。2026-09-13 包含小版本為 7.25 還有 16 天，主要版本猜測模式為 7.3 還有 51 天。
3. 公告、預告及推測的日期提示改用今天，當日分別標示「公告於／預定／推測今日更新」，隔日才提示日期已過。`next.overdue` 保留為核對日的相容欄位，畫面不再依賴它；即使頁面跨過 9/29，也只提示實際更新待核對，不自動切換繁中現行版本。表格與詳情的歷史已上線版本、無獨立日期的合併版本與隱藏日期的同步候選不新增提示。國際服月份公告另由 Node 提供 `international_month_end_day`，整個月份經過後才提示；例如 8.0 的 2027/01 在 2/1 才顯示月份已過，不把月中圖表錨點當成確切上線日。
4. 猜測圖表的核對日虛線標示為「目前時間線」，位置仍代表已核對進度的截止日；另加中性色實線與「今天 YYYY/MM/DD」標記，位置由同一日期比例尺每日投影。標記不攔截圖表點擊，文字直接顯示且具可讀名稱；兩行標註分開保留空間，窄螢幕限制文字位置並沿用水平捲動，避免與目前時間線或版本節點重疊。猜測模式中，兩服實際線尾的服別及版本標籤置於右下方，避開向右延伸的推測虛線；一般模式維持右側置中。今天超出圖表日期範圍時收起日期線、顯示需重新核對排程，不將今天夾到錯誤的邊界位置。一般模式仍將實際折線延伸至今天。

上述倒數於 2026-09-13 為小版本 779 天、主要版本 639 天；開服至追上則仍為 1056／916 天。日期前、當日、過期、月底及跨日返回均由 `src/utils/versionProgress.js` 與 Vue 時鐘的測試驗證，摘要另編譯實際 Vue 模板做隔離渲染。

## 更新與驗證

### 猜測模式與預定時程

「開服以來的追趕歷程」與「每一版，走了多久」各有一個同步的猜測模式開關，預設關閉；`guess=1` 保存於分享網址，支援重載、上一頁／下一頁，切往其他頁面時清除。開關與 `patchScope`、`patch` 共用選取正規化；無效的 `guess` 值視為關閉。

`scripts/version_progress_forecast.mjs` 在 Node 建置層產生獨立的 `forecast`，方法版本為 `moving-release-cadence-v9`：

1. 各服取最近至多三個已完成的主版週期，至少各有兩筆正間隔樣本才推算。國際服只使用同資料片相鄰主版的週期，中位數取整週後延伸，一般主版目前為 133 天；.5 到下一資料片另計，不混入此中位數。繁中服依使用者指定的 `forecast_policy: {tc_main_cycle_days: 100, tc_update_weekday: 2}`，每個主版以約 100 天為目標並對齊星期二，一般為 14 週、98 天；歷史中位數 115 天僅供參考，不冒稱為本次推測週期。舊設定未填 `forecast_policy` 時，繁中服仍採歷史週期與原日曆日。目標週期須為至少 7 天的整數，星期採 0（日）至 6（六）。
2. 沒有公告、活動預告或指定固定間隔的下一個小版本，才使用近期匹配版本間隔比例估算：最近至多三次抵達小版的繁中／國際天數比，至少兩筆才套用中位比例。其餘小版以國際服在主版週期中的相對位置分配，再對齊可用範圍內最近的星期二。固定日期先切分區間，倒推保留後續小版的更新日，再依序安排，避免同日、倒序、早於國際服或超過下個主版。沒有足夠更新日的固定排程須明確報錯，不捏造日期。兩種篩選共用同一份日期模型；公告與活動預告優先且不改期。

`forecast.rows/groups/stages/tc/international` 提供完整情境視圖。日期日序可以包含推測，但正式日期字串、`released` 旗標、合併註記與來源維持原值；新增 `international_estimated`、`tc_estimated` 及選填 `international_month` 區分狀態。Vue 切換時只選擇實際或情境視圖，摘要的目前版本、固定上線間隔與節點差仍使用實際資料。

情境列的 `lag_days` 由 Node 以「繁中服日序－國際服日序」計算，包含活動預告、單服推測及雙服推測；任一日期缺少時保留 `null`。含推測或活動預告的日期另標示 `lag_estimated: true`，版本面板與選取詳情顯示「約 X 天」；已核對或已有雙服正式公告日期時顯示「X 天」。主要版本與包含小版本共用同一版本的日曆差。情境中的已核對現行列也固定顯示歷史發布日差，不累加繁中發布後經過的天數；未來情境間隔同樣不隨今天平移。一般模式與摘要仍只使用已上線的實際資料；9.0 的數值留在模型內，畫面依既有規則維持合併同步提示。

首次完整小版本交會後，中央情境再尋找下一個國際主版及所屬小版，輸出 `continuation_major: {patch, end_patch, end_day, international_date, tc_date, previous_major, tc_cycle_days}`。`end_patch` 為該組最後小版本，`end_day` 採整組所有有效雙服日期的最大值，完整納入 8.55、8.56 等末期小版。這一步只決定顯示範圍，沿用完整模擬的雙服日期、一般主版週期與固定小版間隔；公告及活動預告日期同樣保留，不因首次追上而將繁中下一主版提前到國際日。當日版本相同不代表之後一定同日更新。下一主版缺少繁中日期或超過 20 年觀察上限時不延伸。

首次完整小版本交會後，另尋找核對日之後第一個由既有排程自然得到雙服同日更新的主版，輸出 `synchronization_start: {patch, day, date}`，並在該列標示 `tc_sync_candidate: true`。這是可能開始同步的候選，不修改任何日期，也不保證其後永久同步；找不到時為 `null`。目前候選為 9.0，兩服約 2029-07-31；若公告或預告改變日期，候選須隨排程重新判定。

兩種篩選保留各自的 `catch_up` 與首次追上累計天數，但共用 `plot_end_day`／`plot_end_date`：採整組後續小版本終點與同步候選日期的較晚者，日期與時長都續算至該日；主要版本篩選仍只列主版。沒有可用延伸主版時，先退回各自的交會日或原本觀察上限，再納入可用的同步候選。此延伸不改變較快／較慢情境的首次交會比較。終點為同步候選時，圖表標示「可能開始同步」，否則保留「推測終點」。末版只累計到觀察終點，內部時長可為 0 天，不冒稱完整版本時長。

延伸主版與同步候選的群組另輸出 `duration_outlook: {international: "unknown", tc: "may_synchronize"}`，其餘推測群組為 `null`，一般模式不加此狀態。包含小版本時，接近同步的 8.5 保留未定提示：國際服總時長顯示「—」，繁中服顯示「可能與國際服同步」；主要版本的推測模式則將兩服總時長都顯示為「—」。累計天數仍保留供守恆檢查。桌面跨列欄位、輔助文字與手機群組摘要共用相同顯示規則；各版日期下方的單版時長仍依下一次更新或觀察終點計算。此提示不表示 8.55 或 8.56 已推算為兩服同日更新。

9.0 等尚無公告或活動預告的同步候選過於遙遠，因此以 `src/utils/versionProgress.js` 的 `僅顯示版本同步` 集中判定呈現方式。只有候選主版的末組保留版本欄，將兩服上線日期、兩服主版總時長及相隔天數五欄合併，置中顯示粗體「繁中服可能於此版本開始與國際服同步更新。」，來源欄保留「情境推測」。手機同樣跨越兩欄呈現提示，不再增加主版總時長摘要，來源另列於右側。選取詳情與兩處推測摘要也只顯示同步提示；圖表省略該版本的節點日期與終點日期，最右日期刻度改為「後續」，敏感度情境若抵達該版亦只顯示版本號。模型日期與時長保留供座標及前版時長使用；後續若加入正式日期或活動預告，回到一般日期呈現。

`forecast_policy.shared_minor_intervals` 保存兩服共用的固定小版間隔，格式為 `{from_expansion: 8, steps: [{from: "0", to: "01", days: 14}, ...]}`。目前從 8.0 起，相同編號的 `.0 → .01`、`.01 → .05`、`.1 → .11` 各為 14 天，`.11 → .15` 為 21 天；9.x 之後同樣套用。這是各服前版到下一版的時長，不是從所屬主版起算的偏移；各服以自己的前版日期為基準，不再按繁中主版比例壓縮，也不套入歷史樣本。既有公告或活動預告日期優先，後續未定日期再從該日期起算。指定間隔排不進可用更新日或主版範圍時報錯，不悄悄縮短。前版沒有獨立繁中日期時，不套用該段固定間隔。

此欄位可省略，以保留舊有估算行為。起始資料片須為正整數，`steps` 須為非空白清單；各段須使用同主版內向後且不重複的編號、正整週天數。輸出 `forecast.shared_minor_intervals` 供兩處摘要說明情境依據；歷史中位數另行保留，例如 `.15` 的歷史主版偏移仍為 42 天，但從 8.0 起的指定排程為主版後 14 + 21 = 35 天。

模式開啟時，各版時長改以同服下一個情境日期計算，主版總時長由所屬小版加總。日期或結束切點含推測時，時長標示 `estimated: true`，顯示「約 X 天・推測」。最後一版只計至情境終點，以 `through_horizon: true` 顯示「計至推測終點」，不假稱完整週期；新版本抵達當日的累計時長可為 0 天。明確省略版本沒有繁中日期與時長。關閉模式即還原截至台灣今日的「持續增加中」時長。

8.56 延續至尚未確定的 9.0，因此兩服日期下方都不顯示 8.56 的推測單版時長；日期、相隔天數及主版總時長仍依原有規則呈現。模型保留時長供內部計算，未來若已有實際時長則可正常顯示。

主要版本的推測模式同樣不顯示 8.5 兩服日期下方的單版時長；繁中服主版總時長移除同步標註，只顯示「—」。時長隱藏規則由頁面的 `隱藏末期主版時長` 集中判定，僅限 `guess=1` 且 `patchScope=major` 的 8.5，保留兩服上線日期；相隔天數欄與選取詳情仍依兩服推測日期顯示間隔，目前為「約 42 天」。切回包含小版本時，8.5 的單版時長與繁中總時長提示恢復原有顯示。

猜測模式圖表維持一個 Vue 管理的 SVG：實際兩服折線止於核對日，後續用各服顏色的虛線與菱形延伸至交會、後續小版及可能開始同步的主版本。圖表高度隨版本數完整展開，不限制預測模式的高度，也不產生圖表內部的垂直捲軸；窄螢幕仍保留左右捲動以維持日期可讀性，主要版本篩選提供較精簡的全程。所有推測節點都能透過點擊、鍵盤或選單查看詳情，表格也完整列出至情境終點的版本；推測版本的選取支援 `guess=1` 分享網址。關閉模式或切換範圍時，選取會退回該視圖可用的版本。

`VersionForecastSummary.vue` 在兩個區塊呈現同步結果、下一個更新、累計追趕天數及可展開的模型假設與敏感度情境。`tc_cycle_source` 區分指定情境與歷史週期，`tc_historical_cycle_days` 保留歷史中位數，`tc_typical_cycle_days` 說明星期對齊後的一般時長。現行繁中目標為 100 天（通常 98 天），國際一般主版為 133 天；7.25 採記者會暨玩家見面會預告的 2026-09-29，下一主版 7.3 約 2026-11-03。主要版本情境約 2028-06-13 在 8.3 交會，包含小版情境約 2028-10-31 在 8.45 交會，均非官方時程。套用指定的 8.x 合併假設後，含小版的較快／較慢情境分別約 2028-07-25（8.4）／2029-07-17（9.0）。繁中 7.2 主版總時長由截至台灣今日的實際累計值（核對日為 46 天）改為推測 98 天，國際 7.5 主版總時長依 8.0 月份內的週二錨點推為 266 天。

- `tc_forecast_skip: true` 是尚未確認的跳版假設，目前設於 7.31、7.38、7.41、7.56，不能與正式日期、活動預告、主版或已確認的 `tc_version_omitted` 混用。7.4 之後只略過使用者指定的 7.41、7.56，7.45、7.51、7.55 保留獨立推測日期。建置器在情境列提供 `tc_forecast_skipped`，只跳過繁中推測更新與時長切點，保留國際服日期、圖表階段、版本選單與完整表格。一般模式仍為「尚未公告改版日期」；猜測模式顯示「推測與其他版本合併」，並明示待官方確認。合併文字在表格與選取詳情使用主題的次要灰色文字，不套用推測日期的黃色；因沒有獨立繁中日期，相隔天數仍顯示「—」。
- `forecast_policy.tc_skipped_patches` 另保存尚未收錄正式日期的未來版本合併假設，目前依使用者指定為 8.16、8.18、8.21、8.31、8.38、8.41。此選填欄位須為不重複的小版本字串清單，不能與已收錄列的正式日期、活動預告或已確認省略狀態衝突；省略時不加入額外假設。Node 產生未來小版時先按完整版本號標記，再安排繁中日期、計算時長與交會。國際節點保留，不增加一般模式的正式版本列，也不指定尚未確認的合併目標。
- 原有 7.x 與新增 8.x 假設共同輸出至 `skipped_patches`，只對完整版本號生效，不自動延伸到 9.x。中央、較快及較慢情境使用同一份清單；8.51、8.56 已依使用者修正移出合併假設，三種情境皆保留獨立繁中日期。合併版本不產生繁中日期或時長，前一個獨立版本延續至下一次更新；主版總時長仍依完整週期加總。這些都是待官方確認的情境，不能升格成 `tc_version_omitted`。

### 維護步驟

核對雙方官方公告與 The Lodestone 更新紀錄後，新增版本列及 HTTPS 來源，再更新 `verified_through`。只在官方有獨立發布日期時填入 `tc`；合併內容須註明已確認的具體範圍。`major` 必須明確填寫，清單維持國際服發布順序，繁中獨立日期亦不可倒序。

執行 `npm run test:version-progress` 檢查日期、截止日、合併內容、來源、分享網址與隔離環境中的 SEO 產出；另外驗證台灣午夜、跨年、閏日、Vue 時鐘跨日／返回刷新／清理，以及兩種範圍下實際時長與主版合計一致。間隔測試涵蓋兩種範圍及猜測開關、跨日與核對日重建後保持固定、7.2 與預定 7.25 同為 490 天，以及正式核對新版本後才更新比較對象與縮短／增加／相同的結果。純前端驗證使用 `node node_modules/vite/bin/vite.js build`，避免觸發 `npm run build` 的使用者資料 prebuild。啟動 Vite 或 preview 仍須遵守 AGENTS.md 第 10 節的明確核准規則。

測試的 postbuild 使用獨立暫存目錄與 HTML 殼層，不讀正式玩家資料；驗證首頁 metadata 仍為排行榜，同時產生版本頁 HTML、OG 與 sitemap。
